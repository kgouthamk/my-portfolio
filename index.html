How I pioneered Agent-Generated UI at League — turning a healthcare chatbot into a surface-adaptive, omnichannel intelligent experience.

Pioneering Agent-Generated UI
League Health · 2025 AG-UI MCP Omnichannel

The problem: Healthcare AI was trapped in a text box. At League, we were building an AI Health Coach — but a plain chat interface creates friction at exactly the moment users need clarity. Rich, visual experiences don't just look better; in healthcare, they lead to meaningfully better outcomes. The challenge: we needed the agent to render care plans as structured cards, medication schedules as visual timelines, and health metrics as clear summaries — not walls of text. But building bespoke UI for every surface and every content type wasn't scalable.

The approach: I drove the vision for Agent-Generated UI — the idea that an agent, given structured semantic intent and the right protocols, could select and populate the right UI component for any content, on any surface, without sacrificing accuracy. The enabling layer: open protocols like AG-UI alongside our proprietary design system. The hard part wasn’t the concept — it was proving accuracy at scale. An AI-populated UI component with incorrect data is not a UX problem — it’s a trust failure. The solution: deterministic data hydration driven by semantic intent, validated through evals and hooks, so visual richness never came at the cost of reliability.

“Rather than debate the architecture in meetings, I built a working prototype — uniting open agent-UI protocols with our proprietary design system in under a month. Showing is always faster than telling.”

The execution: Building the prototype was as much an exercise in cross-functional leadership as it was in engineering. Working closely with product, engineering, and design partners, we aligned around the architecture through a live demonstration — addressing natural questions about protocol portability, design system compatibility, and performance through a working system rather than a slide deck. The prototype used CopilotKit and AG-UI to render the same content as a rich card widget in-app, as structured HTML in email, as concise formatted content in SMS, and as audio narration for voice. Same semantic intent — adapting intelligently to every surface. Evals validated that rendered content always matched verified source data: nothing inferred, nothing fabricated.

The surfaces the agent now supports:

In-App (UI SDK) SMS / MMS WhatsApp / Messenger Chat Apps (Claude, Gemini, ChatGPT) Voice / VoIP Email (HTML) Push Notifications

The outcome: The team’s reaction when we demonstrated the prototype was that it felt magical — not because of visual polish, but because it did what the theory promised: the same intelligence adapting seamlessly to every surface and context. What started as a month-long prototype became a foundational platform architecture, transforming the agent from a conversational interface into a true omnichannel intelligent partner — one that meets users wherever they already are and communicates in the language of that surface.
